## 1. 프로젝트 개요

### 1-1. 한 줄 정의

> 유저의 7일치 플레이 로그를 AI가 분석하여 이탈 위험을 감지하고, 다음 접속 시 NPC가 자연스럽게 개입해 잔존과 결제를 유도하는 통합 파이프라인

### 1-2. 해결하려는 문제

| 문제 | 현황 |
|---|---|
| 유저 이탈 | 모바일 RPG 평균 월 이탈률 20~50% |
| 획일적 개입 | 모든 유저에게 동일한 팝업/프로모션 노출 |
| BM 규제 리스크 | 확률형 아이템 단일 의존 구조 |
| 운영 비효율 | 수작업 이벤트 기획으로 개인화 불가 |

### 1-3. 핵심 접근

```
[7일치 플레이 로그]
        ↓
[배치 분석 - 이탈 확률 산출]
        ↓
[개입 시나리오 결정]
        ↓
[다음 접속 시 NPC 트리거]
  "요즘 강화가 잘 안 풀리는 것 같군..."
        ↓
[퀘스트 / 맞춤 상품 연결]
```

## 3. 경쟁사 및 유사 사례 비교 분석

### 3-1. 국내외 주요 사례

#### NCSoft — Blade & Soul 이탈 예측 (2017)

- **방식:** 플레이 로그 기반 이탈 확률 예측 (ML 분류 모델)
- **데이터:** 82종 로그 타입, 10,000명, 100GB
- **결과:** 이탈 분류 F1 Score 0.62 (IEEE CIG 2017 경진대회)
- **한계:** 예측에 그침. NPC 개입이나 개인화 추천으로 이어지는 파이프라인 미공개

#### NetEase — perCLTV 시스템 (2022)

- **방식:** 이탈 예측 + 결제 예측을 동시에 수행하는 멀티태스크 학습
- **데이터:** 다수 게임의 순차 행동 로그 + 소셜 그래프
- **결과:** A/B 테스트에서 이탈 개입 효과 유의미 확인
- **한계:** 개입 방식이 팝업/프로모션 수준. NPC 대화 기반 자연스러운 개입 없음

#### Rovio — ML 기반 난이도 개인화 (2019~)

- **방식:** 강화학습으로 유저별 난이도 조절 → 이탈 지점 예방
- **결과:** Angry Birds Dream Blast 출시 6개월 내 €60M 매출
- **한계:** 난이도 조절에 특화. RPG 강화/성장 구조에 직접 적용 불가

#### Tribal Casino — 개입 타이밍 최적화

- **방식:** D7/D30 지점에서 이탈 개입 트리거 설정
- **결과:** 이탈 시점 D30 → D45로 연장, LTV $420 → $615 **(+46%)**

#### King of Thieves — 리텐션 최적화

- **결과:** D1 리텐션 26% → 57%, D7 리텐션 9% → 32%, LTV **25배 개선**

### 3-2. 학술 연구 현황

| 연구 | 핵심 내용 | 한계 |
|---|---|---|
| CHI 2023 — 개인화 퀘스트/NPC 대화 생성 | 지식 그래프 + LLM으로 플레이어 진행 상황에 맞는 NPC 대화 생성 | 이탈 감지와 연결 없음 |
| PLOS One 2017 — 캐주얼 게임 이탈 예측 | 193,443명, 로그 기반 XGBoost/LSTM 비교 | 예측만, 개입 없음 |
| MDPI 2022 — F2P 모바일 이탈 개입 실험 | 80M+ 플레이어, 무료 재화 지급 개입 실험 | **효과 없음** — 비개인화 개입의 한계 증명 |

> **MDPI 2022 논문의 핵심 교훈:** 무차별적 보상 지급은 이탈율에 유의미한 영향 없음.  
> **맥락에 맞는 개인화 개입**이 핵심임을 역설적으로 증명.

## 4. 차별점 및 전략적 포지셔닝

### 4-1. 핵심 차별점

각 구성 요소는 이미 검증된 기술이지만, 세 가지를 **하나의 파이프라인으로 연결**한 공개 구현체는 존재하지 않음.

```
[이탈 감지]  +  [NPC가 과거 행동을 참조한 자연스러운 개입]  +  [맞춤 퀘스트/상품 연결]
     ↑                        ↑                                        ↑
  검증됨                   신규 결합                               검증됨
(NCSoft, NetEase)       (공개 사례 없음)                       (NetEase, Rovio)
```

### 4-2. MDPI 2022 논문이 증명한 것

> 비개인화 개입(무료 재화 지급)은 효과가 없었다.

본 프로젝트는 이 실패 사례를 반면교사 삼아:
- 이탈 **원인별** 시나리오 분기
- 게임 세계관 **맥락에 맞는** NPC 대화
- 유저가 AI 개입인지 **느끼지 못하는** 자연스러운 흐름

을 설계함.

## 5. 시스템 설계

### 5-1. 전체 아키텍처

```
┌─────────────────────────────────────────────────┐
│                  게임 서버                        │
│  플레이 이벤트 로그 → S3 적재 (실시간)             │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│            배치 분석 파이프라인 (1일 1회)          │
│                                                  │
│  S3 로그 → Athena 쿼리 → Feature Engineering     │
│                              ↓                   │
│                    이탈 예측 모델 (XGBoost)        │
│                              ↓                   │
│              이탈 확률 + 원인 분류 결과 저장        │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│           시나리오 엔진 (개입 결정)               │
│                                                  │
│  이탈 원인 → NPC 시나리오 매핑                    │
│  유저 상태 → 추천 상품/퀘스트 선택                │
│  개입 여부 결정 (빈도 제한 포함)                   │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│            게임 클라이언트 (다음 접속 시)          │
│                                                  │
│  NPC 트리거 → 개인화 대화 → 퀘스트/상품 제안      │
└─────────────────────────────────────────────────┘
```

### 5-2. 플레이 로그 스키마

| user_id | STRING | 유저 고유 ID |

| event_result | STRING | 결과 (success/fail/cancel) |

### 5-3. Feature Engineering (7일치 → 모델 입력)

```python
# 유저별 7일 집계 Feature 예시

features = {
    # 접속 패턴
    "session_count_7d": "최근 7일 접속 횟수",
    "avg_session_min_7d": "평균 세션 시간(분)",
    "session_trend": "세션 시간 증감 추세 (후반 3일 / 전반 4일)",
    "days_since_last_login": "마지막 접속 이후 경과일",

    # 행동 패턴
    "enhancement_attempts_7d": "강화 시도 횟수",
    "enhancement_fail_rate": "강화 실패율",
    "quest_clear_7d": "퀘스트 클리어 수",
    "stage_stagnation_days": "동일 구간 정체 일수",

    # 사회 활동
    "guild_yn": "길드 가입 여부",
    "party_play_ratio": "파티 플레이 비율",

    # 경제 활동
    "purchase_count_7d": "7일 내 결제 횟수",
    "purchase_amount_7d": "7일 내 결제 금액",
    "last_purchase_days_ago": "마지막 결제 이후 경과일",

    # 성장
    "level": "현재 레벨",
    "level_gain_7d": "7일 내 레벨 상승",
}
```

### 5-4. 이탈 감지 모델

- **알고리즘:** XGBoost (경량, 해석 가능, 업계 표준)
- **라벨 정의:** 마지막 로그 이후 14일 이상 미접속 = 이탈 (1)
- **출력:** 이탈 확률 (0~1) + 이탈 원인 분류

**이탈 원인 분류 (Rule-based 후처리)**

```
이탈 확률 > 0.6 이고:
  enhancement_fail_rate > 0.7  →  원인: "강화_실패"
  stage_stagnation_days > 5    →  원인: "구간_정체"
  session_trend < 0.4          →  원인: "접속_감소"
  purchase_amount_7d == 0
    AND last_purchase_days_ago > 30  →  원인: "결제_이탈"
  그 외                        →  원인: "일반_피로"
```

### 5-5. NPC 시나리오 엔진

**원인별 시나리오 매핑**

| 이탈 원인 | 트리거 NPC | 대사 패턴 | 제안 내용 |
|---|---|---|---|
| 강화_실패 | 대장장이 | "요즘 강화가 잘 안 풀리는 것 같군... 이 재료를 써보게" | 강화 성공률 보조 아이템 퀘스트 |
| 구간_정체 | 용사 길드장 | "혼자 하기 버거운 구간이지. 같이 도전해볼 동료를 소개해줄까?" | 파티 매칭 + 구간 클리어 퀘스트 |
| 접속_감소 | 마을 상인 | "오랜만에 보는군. 자리 비운 사이 특별한 물건이 들어왔네" | 복귀 보상 이벤트 + 한정 아이템 |
| 결제_이탈 | 모험가 협회장 | "자네 실력이라면 이 임무에 딱인데... 특별 지원도 해주지" | 첫 결제 할인 or 배틀패스 제안 |
| 일반_피로 | 여관 주인 | "오늘은 푹 쉬다 가게. 특별히 오늘만 쓸 수 있는 걸 드리지" | 소모성 버프 아이템 증정 |

**개입 제한 규칙**
- 세션당 최대 1회 트리거
- 동일 시나리오 연속 3회 이상 금지
- 유저 옵트아웃 설정 시 전체 개입 중단

## 7. 구현 로드맵

### Phase 1 — 데이터 파이프라인 + 이탈 감지 모델 (1~3개월)

```
Week 1-2:  Blade & Soul 데이터 전처리 및 EDA
Week 3-4:  Feature Engineering (7일 집계)
Week 5-6:  XGBoost 이탈 예측 모델 학습 및 평가
Week 7-8:  이탈 원인 분류 로직 구현
Week 9-12: A/B 테스트 시뮬레이션 (개입군 vs 대조군)
```

**Go 기준:** 이탈 예측 AUC > 0.75

### Phase 2 — NPC 시나리오 엔진 + 추천 (4~6개월)

```
Week 13-16: 시나리오 매핑 엔진 구현

Week 21-24: 통합 파이프라인 연결 및 시뮬레이션 검증
```

**Go 기준:** 시뮬레이션 상 개입군 세션 유지율 대조군 대비 +10%

## 8. KPI 및 성공 기준

### 8-1. 목표 KPI

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 이탈 예측 AUC | > 0.75 | 테스트셋 평가 |
| AI 개입 후 세션 유지율 | 대조군 대비 +10% | A/B 테스트 시뮬레이션 |
| D7 리텐션 | +5%p | 파일럿 실측 |
| 맞춤 상품 CVR | +3%p | 파일럿 실측 |
| LTV | +15% | 확대 적용 후 실측 |

### 8-2. Go/No-Go 기준

| 단계 | 통과 기준 | 실패 시 |
|---|---|---|
| Phase 1 | AUC > 0.75 | 피처 재설계 후 재실험 |
| Phase 2 | 세션 유지율 대조군 +10% | 시나리오 전면 재검토 |
| Phase 3 | AI 인프라 비용 < 증분 매출의 40% | 모델 경량화 또는 대상 축소 |

### 8-3. 모니터링 지표

- 유저 옵트아웃 비율 (> 20% 시 개입 방식 재검토)
- NPC 개입 후 CS 인입 건수 (대조군 대비 2배 초과 시 중단)
- 개입 시나리오별 효과 분포 (특정 시나리오 편중 시 다양화)
